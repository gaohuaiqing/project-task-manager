# 延期双视角统计 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 延期计数从「按当前 assignee 归属」改造为「按延期发生时负责人归属」，提供任务视角（明细+当时负责人）与责任人视角（P3 事件口径+下钻），历史数据经 task_delayed 通知直连回填（v2，审计锚已证伪）。

**Architecture:** 一次幂等迁移（065 加列+回填）奠定数据基础；写入点实时快照保证新数据；analytics 4 处旧口径消费点切换为事件口径；新增 delay-events 明细 API 供报表明细表与 P3 下钻共用。

**Tech Stack:** Express + mysql2（后端 CJS 编译 `tsconfig.cjs.json`）、React + TypeScript、MySQL 8.4 JSON 函数。

**Spec:** `docs/superpowers/specs/2026-11-06-延期双视角统计-design.md`

```typescript
/**
 * 数据库迁移 065: delay_records 加 assignee_id 列 + 历史回填
 *
 * 目标：
 * 1. delay_records 加 assignee_id INT NULL + 索引（「当时负责人」快照，NULL=未知/未分配）
 * 2. 历史回填按 task_delayed 通知直连（spec 4.2 v2 算法，审计锚已证伪）：
 *    cron 写 delay_records 的同一循环发 task_delayed 通知给当时负责人
 *    （task_id 正确 UUID + user_id=当时 assignee + 同秒时间戳）→ 事件级 1:1 直连
 *    无匹配 + 事件时已指派（任一条 task_assigned 通知 ≤ 事件时间）→ 当前 assignee 兜底
 *    无匹配 + 事件早于全部指派通知（当时未分配）→ 保持 NULL（展示「未分配」）
 *
 * 幂等性：
 * - run-migration.ts migrations 表保证只执行一次
 * - 加列前 INFORMATION_SCHEMA 检查；回填 WHERE assignee_id IS NULL 可安全重跑
 *
 * 注意：assignee_id 不加外键（回填值可能指向已删用户；悬空时 JOIN 不到名字显示「未知」）
 */
import { getPool } from '../core/db';
import type { RowDataPacket, ResultSetHeader } from 'mysql2/promise';

const MIGRATION_VERSION = '065';

async function columnExists(table: string, column: string): Promise<boolean> {
  const pool = getPool();
  const [rows] = await pool.execute<RowDataPacket[]>(
    `SELECT COUNT(*) AS cnt FROM INFORMATION_SCHEMA.COLUMNS
     WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = ? AND COLUMN_NAME = ?`,
    [table, column]
  );
  return Number(rows[0]?.cnt) > 0;
}

export async function up(): Promise<void> {
  console.log(`[Migration ${MIGRATION_VERSION}] delay_records 加 assignee_id 列...`);
  const pool = getPool();

  // 1. 加列（幂等）
  if (!(await columnExists('delay_records', 'assignee_id'))) {
    await pool.execute(
      `ALTER TABLE delay_records
       ADD COLUMN assignee_id INT NULL COMMENT '延期发生时的负责人快照（历史按task_delayed通知直连回填）' AFTER recorded_by,
       ADD INDEX idx_delays_assignee (assignee_id)`
    );
    console.log(`[Migration ${MIGRATION_VERSION}] assignee_id 列已添加`);
  } else {
    console.log(`[Migration ${MIGRATION_VERSION}] assignee_id 列已存在，跳过 ALTER`);
  }

  // 2. dry-run 统计（回填前）
  const [before] = await pool.execute<RowDataPacket[]>(
    `SELECT COUNT(*) AS total,
            SUM(CASE WHEN assignee_id IS NULL THEN 1 ELSE 0 END) AS unfilled
     FROM delay_records`
  );
  console.log(`[Migration ${MIGRATION_VERSION}] 回填前: 总事件 ${before[0].total}, 未填 ${before[0].unfilled}`);

  // 3. 回填①：通知直连（ROW_NUMBER 窗口防歧义——±120s 内多条通知取时间差最小一条）
  const [r1] = await pool.execute<ResultSetHeader>(
    `UPDATE delay_records dr
     JOIN (
       SELECT dr_id, user_id FROM (
         SELECT dr2.id AS dr_id, n.user_id,
                ROW_NUMBER() OVER (PARTITION BY dr2.id
                  ORDER BY ABS(TIMESTAMPDIFF(SECOND, n.created_at, dr2.created_at))) AS rn
         FROM delay_records dr2
         JOIN notifications n ON n.type = 'task_delayed'
           AND n.task_id = dr2.task_id
           AND ABS(TIMESTAMPDIFF(SECOND, n.created_at, dr2.created_at)) <= 120
         WHERE dr2.assignee_id IS NULL
       ) w WHERE w.rn = 1
     ) pick ON pick.dr_id = dr.id
     SET dr.assignee_id = pick.user_id
     WHERE dr.assignee_id IS NULL`
  );
  console.log(`[Migration ${MIGRATION_VERSION}] 回填①通知直连: ${r1.affectedRows} 行`);

  // 4. 回填②：兜底当前 assignee——仅限「事件时任务已有指派」（任一条 task_assigned 通知 ≤ 事件时间）；
  // 事件早于全部指派通知 = 当时未分配 → 保持 NULL（展示「未分配」，绝不把旧账记给后上任的负责人）
  const [r2] = await pool.execute<ResultSetHeader>(
    `UPDATE delay_records dr
     JOIN wbs_tasks t ON dr.task_id = t.id
     SET dr.assignee_id = t.assignee_id
     WHERE dr.assignee_id IS NULL
       AND EXISTS (
         SELECT 1 FROM notifications n
         WHERE n.type = 'task_assigned' AND n.task_id = dr.task_id
           AND n.created_at <= dr.created_at
       )`
  );
  console.log(`[Migration ${MIGRATION_VERSION}] 回填②当前值兜底(仅已指派): ${r2.affectedRows} 行`);

  // 4. dry-run 统计（回填后）
  const [after] = await pool.execute<RowDataPacket[]>(
    `SELECT COUNT(*) AS total,
            SUM(CASE WHEN assignee_id IS NULL THEN 1 ELSE 0 END) AS unfilled
     FROM delay_records`
  );
  console.log(`[Migration ${MIGRATION_VERSION}] 回填后: 总事件 ${after[0].total}, 未填 ${after[0].unfilled}`);
}
```

- [ ] **Step 1: 抽公共辅助查询**（repository 类内新增私有方法，供 4 处复用，DRY）：

```typescript
  /**
   * 事件归属口径：按 dr.assignee_id 聚合延期事件次数（双视角核心查询）
   * @param scopeFilter 权限范围（作用在任务/项目别名 t./p. 上，dr JOIN 后沿用）
   * @param sd/ed 时间段（可选，过滤 dr.created_at）
   * @param projectId 项目筛选（可选）
   */
  private async countDelayEventsByAssignee(
    scopeFilter: ScopeFilter,
    sd?: string,
    ed?: string,
    projectId?: string
  ): Promise<Map<number, { name: string; deptId: number; count: number }>> {
    const pool = getPool();
    const conds = [scopeFilter.clause];
    const params: (string | number)[] = [...scopeFilter.params];
    if (sd && ed) { conds.push('dr.created_at BETWEEN ? AND ?'); params.push(sd, ed); }
    if (projectId) { conds.push('t.project_id = ?'); params.push(projectId); }
    const [rows] = await pool.execute<RowDataPacket[]>(
      `SELECT dr.assignee_id,
              IF(dr.assignee_id IS NULL, '未分配', COALESCE(u.real_name, u.username, '未知')) AS assignee_name,
              COALESCE(u.department_id, 0) AS dept_id,
              COUNT(*) AS event_count
       FROM delay_records dr
       JOIN wbs_tasks t ON dr.task_id = t.id
       JOIN projects p ON t.project_id = p.id
       LEFT JOIN users u ON dr.assignee_id = u.id
       WHERE ${conds.join(' AND ')}
       GROUP BY dr.assignee_id, u.real_name, u.username, u.department_id`,
      params
    );
    const m = new Map<number, { name: string; deptId: number; count: number }>();
    for (const r of rows as RowDataPacket[]) {
      m.set(Number(r.assignee_id), {
        name: String(r.assignee_name ?? '未知'),
        deptId: Number(r.dept_id) || 0,
        count: Number(r.event_count) || 0,
      });
    }
    return m;
  }
```

  - 回填（指派通知区间法，生效时点 `COALESCE(approved_at, created_at)`）：
    ```sql
    UPDATE plan_changes pc
    JOIN (
      SELECT pc_id, user_id FROM (
        SELECT pc2.id AS pc_id, n.user_id,
               ROW_NUMBER() OVER (PARTITION BY pc2.id ORDER BY n.created_at DESC) AS rn
        FROM plan_changes pc2
        JOIN notifications n ON n.type = 'task_assigned'
          AND n.task_id = pc2.task_id
          AND n.created_at <= COALESCE(pc2.approved_at, pc2.created_at)
        WHERE pc2.assignee_id IS NULL
      ) ranked
      WHERE rn = 1
    ) m ON pc.id = m.pc_id
    SET pc.assignee_id = m.user_id
    WHERE pc.assignee_id IS NULL
    ```
  - 回填后统计：总行数 / 未填数（预期未填 = 生效时点早于全部指派通知的行，语义=当时未分配）
