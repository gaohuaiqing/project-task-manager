# 「逾期未开始」（overdue_start）状态实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增第 9 个互斥任务状态「逾期未开始」（overdue_start），识别"计划开始日期已过但未实际开始"的任务，覆盖 WBS 表 / 仪表板 / 延期报表 / 消息通知四个模块。

**Architecture:** 在现有 8 状态互斥状态机中插入新分支（机制零变更，仅加判断+登记）。优先级链：pending_approval > 完成三态 > delayed > delay_warning > **overdue_start(新)** > in_progress > not_started。not_started 同步收窄（排除 start_date 已过）。状态计算共 5 处同步点必须一致。

**Tech Stack:** React + TypeScript + Tailwind（前端），Express + mysql2 + node-cron（后端），MySQL ENUM 列需迁移 064。

**需求文档:** `docs/requirements/FINAL_REQUIREMENTS_0920-1428.md` 模块#8 规则6（权威口径）

## Global Constraints

- **判定口径（与需求文档一致）**: 无实际开始日期 && 无实际结束日期 && `start_date < 当天` && 不处于 delayed/delay_warning（即 `end_date IS NULL OR end_date >= 当天 + warning_days`）。`end_date` 为空的任务同样适用。
- **既有状态含义一律不改**：delayed / delay_warning / 完成三态的判定条件保持逐字不变。
- **pendingTasks 合计口径**：仪表板「待处理任务」与每日摘要的 pending 数字 = `not_started + overdue_start` 之和（既有卡片数字不突变）。
- **通知节奏**：首次进入逾期未开始发一次 + 每逾期 7 天再发；接收人：任务负责人。
- **报表口径**：仅当前口径（当前处于 overdue_start 的任务），不做历史追溯。
- **DB 迁移**: `wbs_tasks.status` 是 ENUM，必须先扩枚举再写数据。⚠️ **生产环境部署时迁移会自动修改生产 DB 结构——回传前必须获得用户单独确认**。
- **注释语言**: 中文（与现有代码库一致）。
- **禁止 git push**（用户未要求时）；每个 Task 结束本地 commit。
- 类型检查命令：后端 `cd app/server && npx tsc --noEmit`；前端 `cd app && npx tsc --noEmit`（若无 tsconfig 覆盖则用 `npm run build`）。
- 本机 dev 环境：后端 3001 / 前端 5173，账号 admin/admin123，本机 MySQL 3306（见 memory「本机dev测试环境」）。

## 状态条件 SQL 权威定义（全计划复用）

以下条件在 5 处同步点逐字一致（仅别名/前缀差异）。互斥性关键：overdueStart 的尾部条件与 notStarted 完全相同，区别仅在 `start_date`：

```
overdueStart（新增）:
  (COALESCE(JSON_LENGTH(t.pending_changes), 0) = 0 OR t.pending_change_type != 'plan_change')
  AND t.actual_start_date IS NULL AND t.actual_end_date IS NULL
  AND t.start_date IS NOT NULL AND t.start_date < CURDATE()
  AND (t.end_date IS NULL OR t.end_date >= DATE_ADD(CURDATE(), INTERVAL COALESCE(t.warning_days, 3) DAY))

notStarted（收窄，在原条件基础上仅追加 start_date 子句）:
  (COALESCE(JSON_LENGTH(t.pending_changes), 0) = 0 OR t.pending_change_type != 'plan_change')
  AND t.actual_start_date IS NULL AND t.actual_end_date IS NULL
  AND (t.start_date IS NULL OR t.start_date >= CURDATE())
  AND (t.end_date IS NULL OR t.end_date >= DATE_ADD(CURDATE(), INTERVAL COALESCE(t.warning_days, 3) DAY))
```

  const [rows] = await pool.execute<RowDataPacket[]>(

    [MIGRATION_VERSION]
  );
  return Number(rows[0].cnt) > 0;
}

async function markMigrationApplied(): Promise<void> {
  const pool = getPool();
  await pool.execute(
    'INSERT INTO schema_migrations (version, name, applied_at) VALUES (?, ?, NOW())',
    [MIGRATION_VERSION, MIGRATION_NAME]
  );
}

export async function up(): Promise<void> {
  if (await isMigrationApplied()) {
    console.log(`迁移 ${MIGRATION_VERSION} 已执行，跳过`);
    return;
  }
  const pool = getPool();
  console.log(`开始迁移 ${MIGRATION_VERSION}: 新增 overdue_start 任务状态...`);

  // 1. 扩展 ENUM（9 值）

     MODIFY COLUMN status ENUM(
       'pending_approval', 'not_started', 'overdue_start', 'in_progress',
       'early_completed', 'on_time_completed', 'delay_warning',

- [ ] **Step 3: 新增扫描查询 getOverdueStartTasks**

repository 新增（通知去重按"7 天内未发过"实现"首次+每7天"节奏）：

```typescript
  /**
   * 获取逾期未开始任务（计划开始日期已过但未实际开始，不处于延期/预警）
   * 通知节奏：首次 + 每逾期7天（7天内已发过则跳过）
   */
  async getOverdueStartTasks(): Promise<Array<{
    id: string; description: string; assignee_id: number | null; project_id: string;
    start_date: Date;
  }>> {
    const pool = getPool();
    const [rows] = await pool.execute<RowDataPacket[]>(
      `SELECT t.id, t.description, t.assignee_id, t.project_id, t.start_date
       FROM wbs_tasks t
       WHERE (COALESCE(JSON_LENGTH(t.pending_changes), 0) = 0 OR t.pending_change_type != 'plan_change')
       AND t.actual_start_date IS NULL AND t.actual_end_date IS NULL
       AND t.start_date IS NOT NULL AND t.start_date < CURDATE()
       AND (t.end_date IS NULL OR t.end_date >= DATE_ADD(CURDATE(), INTERVAL COALESCE(t.warning_days, 3) DAY))
       AND NOT EXISTS (
         SELECT 1 FROM notifications n
         WHERE n.link = CONCAT('/tasks/', t.id)
         AND n.type = 'overdue_start'
         AND n.created_at >= DATE_SUB(NOW(), INTERVAL 7 DAY)
       )`
    );
    return rows as Array<{ id: string; description: string; assignee_id: number | null; project_id: string; start_date: Date }>;
  }

  /**
   * 批量刷新逾期未开始状态（幂等，实时条件全量，不依赖旧 status）
   */
  async refreshOverdueStartStatuses(): Promise<number> {
    const pool = getPool();
    const [result] = await pool.execute<ResultSetHeader>(
      `UPDATE wbs_tasks
       SET status = 'overdue_start'
       WHERE status IN ('not_started', 'overdue_start')
       AND actual_start_date IS NULL AND actual_end_date IS NULL
       AND start_date IS NOT NULL AND start_date < CURDATE()
       AND (end_date IS NULL OR end_date >= DATE_ADD(CURDATE(), INTERVAL COALESCE(warning_days, 3) DAY))`
    );
    return result.affectedRows;
  }
```
