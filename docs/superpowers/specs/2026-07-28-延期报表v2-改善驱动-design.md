## 1. 核心目的

**延期报表的核心目的是驱动改善**，而非单纯展示数据：
1. **识别"人"**——哪些人经常延期
2. **识别"任务"**——哪些任务经常延期/变更计划
3. **横向对比**（团队间、个人间）+ **纵向对比**（时间趋势/改善方向）
4. 通过对比产生刺激，驱动团队/个人改善

每个视图都必须服务"识别问题 + 对比刺激 + 驱动改善"。

## 2. 四条全局原则（适用所有视图）

### 原则1：含已完成任务（口径扩展）
- v1 仅看 `delayed`（当前未完成延期：`actual_end_date IS NULL AND end_date < CURDATE()`）
- v2 扩展为 **`delayed` + `overdue_completed`**（已完成但曾延期：`actual_end_date IS NOT NULL AND actual_end_date > end_date`）
- 即"曾延期任务"都纳入审视（不止当前未完成），含历史已解决的延期
- **不含** `delay_warning`（预警，未实际延期）
- 复用现有 `DELAY_CONDITIONS.delayed` / `DELAY_CONDITIONS.overdue_completed`

### 原则2：时间段筛选（两视角）
- **当前视角**（实时快照）：基于 `CURDATE()`，不限时间段
- **时间段视角**：选定 `[start, end]`，统计该时间段内 `end_date` 落入区间的任务的延期/变更
- FilterBar 提供 5 个时间预设：**当前视角**（实时快照）/ **近30天** / **近3个月** / **近半年** / **近一年**
- 趋势/改善方向基于时间段

### 原则3：团队层 + 个人层
- 团队层（组/项目/类型维度聚合）
- 个人层（成员维度）
- 统计卡两层都呈现；排名视图按层区分

### 原则4：横向 + 纵向对比（含改善方向）
- 横向：实体间对比（组/人/项目/任务排名）
- 纵向：时间趋势 + **改善方向**（本期 vs 上期，↑恶化/↓改善/→持平）
- 改善方向：本期（选定时间段）vs 上期（前一同等长度时间段）的延期数/率变化

## 4. 关键技术变化

### 4.1 口径扩展（后端）
- 所有"延期"统计从 `DELAY_CONDITIONS.delayed` 扩展为 `delayed OR overdue_completed`
- 抽象为常量 `DELAY_OR_OVERDUE = (delayed OR overdue_completed)`（不含 delay_warning）
- 复用于：统计卡、成员排名、问题任务榜、项目/类型/原因维度、趋势、明细

### 4.2 时间段筛选（后端）
- `ReportQueryOptions` 已有 `start_date` / `end_date`（FilterBar 传）
- 各查询加时间段条件：`t.end_date BETWEEN ? AND ?`（时间段视角）；null 时为当前视角（CURDATE 快照）
- 统计卡同时算"当前值"（无时间段）+ "时间段值"（有时间段）

### 4.3 改善方向（后端 + 前端）
- 本期 = 选定时间段 [start, end]；上期 = [start - N, start - 1]（N = 时间段天数）
- 后端计算两窗口的延期数（含已完成），`delta = current - previous`，`direction = improving/worsening/flat`
- 组对比/项目/成员（改善之星）都需改善方向字段

### 4.4 拆专项排行
- 成员排名：3 专项（延期次数/计划变更/改善之星），后端 `member_ranking` 加 `improvement_delta` 字段（每人本期vs上期），前端拆 3 柱图
- 问题任务：3 专项（反复延期/频繁变更/超长延期天数），后端加 K3 `longest_delay_tasks`（按 `delay_days`）

### 4.5 去掉严重度
- 删除 `SeveritySection` 组件 + 后端 `severity_distribution` 字段（或保留接口字段不渲染，前端不调用）

## 5. 后端实现要点

### 5.1 新增/修改字段
- `DepartmentDelayStat` 加 `improvement_direction` + `improvement_delta`（组改善方向）
- `MemberDelayStat` 加 `improvement_delta`（个人改善，用于改善之星排行）
- `ProjectDelayStat` 加 `improvement_direction`
- `DelayAnalysisReport` 加 `longest_delay_tasks`（K3）、`stats_overview`（重设的统计卡：3指标×当前/时间段×团队/个人）

### 5.2 口径常量
```typescript
const DELAY_OR_OVERDUE = `(${DELAY_CONDITIONS.delayed} OR ${DELAY_CONDITIONS.overdue_completed})`;
```
所有延期统计用此（替代单 `delayed`）。

### 5.3 时间段双视角
统计卡两查询：当前视角（无时间段）+ 时间段视角（有 `t.end_date BETWEEN`）。其余视图按 FilterBar 时间段（有则时间段，无则当前）。

### 5.4 改善方向计算
```typescript
// 本期 vs 上期延期数（含已完成）
const currentPeriod = await countDelayedOrOverdue(start, end);
const periodDays = daysBetween(start, end);
const prevStart = subDays(start, periodDays);
const previousPeriod = await countDelayedOrOverdue(prevStart, start);
const delta = currentPeriod - previousPeriod;
const direction = delta < 0 ? 'improving' : delta > 0 ? 'worsening' : 'flat';
```

### 5.5 trend delayed bug 修复
重设计 `delay_trend` SQL：`created` = 当天**新增**延期数（end_date = 当天的延期任务数），`completed` = 当天**解决**的延期数，`delayed` = 当天**净未解决**（累计新增 - 累计解决）。或简化为"当天末未解决延期数"（单调合理）。
